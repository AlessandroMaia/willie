# v0.1.0 (unreleased)

First slice: the workspace and its development tooling, the architecture
documents, and F0 — the Willie distribution, its daemon and the Dashboard
health view, in a per-user Windows installer.

## Added

- Cargo workspace with the core, protocol, harness, plugin and platform
  crates, each compiling with one test.
- Development tooling: pinned toolchain, `just` recipes, `cargo xtask`
  (`doctor-tools`, `check-refs`, `build-linux`, `distro`), pre-commit
  hook, strict formatting and lints.
- Tauri 2 + React application shell showing the running version.
- Architecture, CLI contract, testing guide and the first decision records.
- The Willie distribution image (Debian slim + Willie binaries), built with
  `just distro-build` and bundled in the installer.
- `willied` answers `daemon.hello`, `daemon.health`, `daemon.doctor` and
  `daemon.shutdown` over stdio; `willie doctor` inside the distribution.
- `willied` serves the `project.*`, `job.*` and `state.*` methods over
  stdio: it owns the projects, runs their git work as background jobs and
  streams `state.event` with a monotonic `seq` from a single writer, so a
  client keeps its view current from one `state.snapshot` plus the events.
- Projects: register a Windows checkout, work on an ext4 clone inside
  the distribution, and sync both ways from the Projects screen;
  `just test-linux` runs the daemon's tests inside the distribution.
- Dashboard: WSL / distribution / daemon / doctor health, install and
  daemon actions, doctor report with remediations.
- Windows installer (NSIS, per-user).
- Sessions (Linux core): the daemon creates, stops, lists and re-adopts
  Claude Code sessions; a detached supervisor owns each PTY and outlives
  the daemon; `willie attach` connects a terminal; the harness is
  detected and installable from the daemon.
- Open a Claude Code session for a project with one click, straight into
  a Windows Terminal tab.
- Open a live session inside the Willie window itself (an embedded
  terminal), as an alternative to the Windows Terminal tab.
- Sessions screen: attach or stop a running session, and see the most
  recently finished ones.
- Install the Claude Code harness from the Dashboard, with progress.
- Resume a project's last conversation with one click (Resume on the
  project row), instead of starting the harness fresh.
- A new look: sidebar navigation with keyboard shortcuts (`Ctrl+1..3`,
  `Ctrl+B`), a status bar with engine health, daemon version and live
  session count, light and dark themes following Windows, and the three
  screens rebuilt on one visual system. Same actions, same behaviour.
- When the WSL 2 VM cannot be created because the virtual-machine
  account lacks "Log on as a service", the Dashboard offers to copy the
  commands that grant it, ready for an elevated prompt or for whoever
  holds administrator rights on the machine.
- A project's sandbox policy can be seen and edited (Sandbox… on the
  project row), and every session now **runs inside it**: a private,
  empty home; the project read-write at its own path; the system
  read-only; the managed tools read-only; no Windows drive outside the
  project, no Windows executable, no reach into Willie's own state. A
  workflow that depended on that reach comes back through `extra.paths`
  in the Sandbox dialog. A share mounted at a custom point under the
  Windows mount root can no longer be named as an extra path: only a
  single-letter drive component is accepted there. An extra path is also
  refused when it names, reaches into, or sits above a location the
  sandbox manages — the managed tools, the package caches, the home
  and the session's own temporary directory, the login, the git
  identity, Willie's own state or the directory every project lives
  under; a path *inside* the home, the temporary directory or that
  projects directory can still be granted one at a time — one project
  can be lent to another, all of them at once cannot. The
  session's event log records what was applied. Resource limits
  (process, descriptor and core) now bound each session, applied from
  inside its own namespace, and the event log records the mechanisms that
  were measured to apply. The syscall filter is now enforced: a session
  cannot trace other processes, touch the mount table, load kernel
  modules, install a syscall filter of its own or open packet and raw
  sockets, and every call it refuses is recorded in the session's event
  log by name, repeats counted rather than repeated. Nested user
  namespaces no longer work inside a session. Landlock now restricts
  each session on top of the mounts: the agent can read and execute
  everywhere it could before, but write only inside the project, its
  caches, its private home and temporary directory, and any extra path
  granted read-write — even through a mount that should not have been
  there; `willie doctor` now reports the real Landlock ABI instead of a
  false skip. A terminal filter now guards the session's output: the
  agent's output can no longer change Willie's terminal tab or window
  title, or write the host clipboard, and each such attempt is recorded
  in the session's event log; everything the terminal draws is unchanged.
- The Sandbox dialog no longer grows past the window. Its rows scroll
  inside it and the buttons stay where they are, so Save is reachable
  however many capabilities the catalogue lists, and the row that
  carries an extra path has room for the path, its mode and its remove
  button on one line.
- The Sessions screen now shows each session's sandbox: the mechanisms it
  applied, anything the kernel could not offer, and the syscalls and
  terminal sequences it denied, with counts.
- A project whose sandbox settings cannot be read no longer disappears:
  its row shows why, Open session and Resume are held until it is fixed,
  and saving from the Sandbox dialog replaces the unreadable settings.
- `willie sandbox explain <project>` now works from inside the
  distribution while the app is open, over the daemon's local socket.
- A session can no longer install a syscall filter of its own through
  `prctl(PR_SET_SECCOMP)`; the attempt is refused and recorded.
- A project row can open its workspace directly in VS Code (Remote-WSL on
  the Willie distribution), so the code is edited in the fast ext4 clone
  instead of the Windows checkout. The action is disabled when VS Code is
  not installed.
- A Tools screen (Ctrl+4) lists the installed agent CLI and its version,
  installs it when missing, and updates it in place. The daemon now
  records what it installed.
- The daemon now hosts plugins: `plugin.list`/`plugin.enable`/
  `plugin.disable` and the `plugins` field of a snapshot expose the
  compiled-in plugins (configuration profiles and usage) and which are
  enabled — a global plugin on or off, a per-project one per project.
  Enablement persists across restarts. A plugin's own methods (today
  `profile.*`) route to it; a plugin that fails or panics is marked
  degraded and never takes the daemon down.
- A Plugins screen (Ctrl+5) enables or disables a global plugin and shows
  which are per-project or degraded.
- A profiles panel, below the plugin list once configuration profiles is
  enabled: create a profile, edit its settings/instructions/MCP fragments,
  check and apply it to a project (with the backup path it wrote), and set
  a remote to push and pull it — a diverged pull is reported rather than
  merged.
- A Usage panel shows each session's context fill and token cost, and a
  per-project token summary, below the plugin list once usage is enabled.
- A new shell: the window loses its native frame for a thin header
  Willie draws itself (its own minimize, maximize and close), and the
  sidebar stops listing screens and becomes the system in front of
  you — its name, workspace path and branch, a live dot when it has a
  session running, and a "…" menu (Open in VS Code, Open in Explorer,
  Update from Windows, Rename, Relocate, Remove) — with that system's
  own four screens beneath it: Session, Sandbox, Profiles, Usage
  (`Ctrl+1`–`Ctrl+4`).
- Everything that used to sit in the sidebar alongside a system's own
  work — the engine's health, Tools, Plugins, the profile store and the
  systems registry, plus Settings — now opens from a drawer behind the
  header's settings button; every old sidebar route redirects to its
  new home, so a bookmark or a muscle-memoried shortcut still works.
- A project can now hold several live sessions at once: the Session
  screen shows one tab per live session, "+" starts a new one, and a
  Sessions panel lists every live session (Open, to switch to its tab)
  and recently finished ones — no more stopping a session just to start
  a second task. Resume is offered on the newest finished agent session
  only: the agent continues the workspace's most recent conversation, so
  resuming an older one would reopen the newest anyway; the others say
  so instead of promising something else.
  Double-clicking a tab's name renames it; a session otherwise names
  itself from its first prompt once the harness has written it.
- A styled interactive shell can now run beside an agent session, under
  the very same sandbox: "+" on the Session screen offers "New zsh" next
  to "New session", with Willie's own prompt showing the branch.
- The workspace tree opens as a drawer from the Session screen, with
  each entry's git status; clicking a file opens a read-only preview
  flush beside it (never over it), with "Open in VS Code" one click away
  for the workspace or for that one file. The tree is reachable whether
  or not the system has a live session, and closes when you leave the
  Session screen.
- A Sandbox screen shows a system's sandbox posture and its
  chronological denial history first — aggregated over every session,
  filterable by session — with the capability switches that used to
  live in a dialog on the project row now reached from a drawer on this
  screen; the status bar shows the same posture for whichever session
  tab is focused, and links to this screen filtered to it.
- A system's Profiles screen says when the profiles plugin is off for
  that system and offers a single Enable, instead of showing the daemon's
  refusal as an error; any other failure is still reported as one.
- A Settings screen lets you pin light or dark instead of following
  Windows automatically, for the current launch — the choice does not
  yet survive a restart.
- Running zsh sessions needs a distribution built with this release:
  `just distro-install` (a fresh install) carries the new package and
  prompt file, but `just distro-push`, which only replaces Willie's own
  binaries, cannot add it to a distribution that predates it.
- The workspace tree, a read-only file preview and the system's shell
  now live in one panel at the right edge, opened from the title bar
  (or Ctrl+J) on any screen instead of only from the Session screen.
  The panel narrows the screen rather than covering it, runs one shell
  per system — adopting one that is already running — and the Session
  screen keeps agent sessions only.
